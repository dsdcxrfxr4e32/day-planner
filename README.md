# Team day planner (box-hosted)

- `server.js`: Node 20 server, no dependencies. Keeps the Asana token server-side ($ASANA_PAT), serves `public/index.html`, exposes a JSON API that proxies Asana.
- `lib.js`: helpers for the D-code (minutes), notes rewriting and dates. `test/lib.test.js` tests them.
- `run.sh start|stop|status`: supervisor loop that restarts the server 3 s after a crash. Log goes to `data/server.log`.
- `data/access_key`: shared-link key. Every request needs `?k=<key>` (otherwise 403). `/healthz` is the only open path.
- Columns follow the Asana due date (Europe/Athens), not plan tags. Today = due today. Tomorrow = due the next calendar day (Friday's Tomorrow is Saturday, not Monday). Monday = due the next Monday strictly after today (if today is Monday, the Monday one week later). A task is in at most one column; when tomorrow is that Monday (a Sunday), it sits in Tomorrow. `TODAY_STORE=asana_tags` (the default) still adds `TODAY-<Name>` when a task is moved to Today (tags are created on first use; gids cached in `data/tag_gids.json`). The planner never creates `TOMORROW-<Name>` or `MONDAY-<Name>` tags. Leftover `TOMORROW-*` tags are ignored for placement and removed from a task when it is moved. `TODAY_STORE=file` stores the three slots in `data/today.json`, `data/tomorrow.json` and `data/monday.json` (box fallback). Today's load counts Today only; there is no automatic roll-over.
- `READ_ONLY=1` refuses every non-GET Asana call (used for tests).
- `apps-script/Code.gs`: an earlier Apps Script port of the server side (not deployed and not needed for the box version).

API (all need k): GET /api/board · POST /api/completed {i, completed} · POST /api/minutes {i, m} · POST /api/today {i, t, prev} · POST /api/clear-today {entries:[{i,t}]} · POST /api/assign {i, a, from} (a = dm/ak/dd/un; the due date keeps the column, and a Today tag moves with the person) · POST /api/plan {i, from, to} (from/to = {s:'t'|'w'|'mo', k} or null for Backlog; moves between Backlog/Today/Tomorrow/Monday and sets due_on to that Athens date, or clears it for Backlog. Tomorrow and Monday do not add a tag) · GET /api/task/:gid (fresh task for the editor) · POST /api/task/:gid {name?, notes?, due_on?} (only changed fields are sent to Asana; notes whose first line is not a D-code get D10M prepended; a name-only save of a task with no D-code also adds D10M; tasks with no D-code count as 10 min)

UI: clicking a card title/body opens an Asana-style edit pane (name, description, due date; Open in Asana link at the bottom). Clicking the due date on a card opens an inline date picker that saves due_on immediately (Clear removes it).

## Client meetings (calendars)
- `cal.js` (uses the npm package `node-ical`; run `npm install` after copying the app) reads each person's Google Calendar secret iCal feed: env `CAL_ICS_DIMITRIS`, `CAL_ICS_ANTONIA`, `CAL_ICS_DIMITRA`, or the same `KEY=VALUE` lines in `data/cal.env` (re-read on every fetch, so a new person can be connected without a restart). The URLs are secret and are never logged or sent to the browser.
- Cached 5 min; the board's ↻ Refresh forces a fresh fetch (`/api/board?refresh=1`).
- A meeting counts when it has an attendee outside @precisegreece.gr (rooms/resources/group calendars ignored) or its title starts with a 3-digit client code. All-day, cancelled and self-declined events are skipped; recurring events (RRULE/EXDATE/overrides) are expanded; overlaps are merged; days are Europe/Athens.
- The board only receives start, end and title of qualifying meetings. Today, Tomorrow, and Monday totals use the same remaining-work rule for Dimitris, Antonia, and Dimitra: open tasks only (completed minutes stay on the "done" line). Today's meetings count only what is left now (ended meetings add nothing, one in progress adds the minutes left, a later one counts in full; overlaps still merge). Tomorrow and Monday meetings count in full, since that day has not started. Show calendar only hides the meeting list; it does not take those minutes out of the totals. All-day and unaccepted events stay uncounted. A person without a feed shows "calendar not connected". There is no Unassigned load card or lane; an unassigned backlog task still shows in gray on a person's board.
- Tests: `npm test` (calendar tests use the synthetic `test/fixture.ics`).

## Columns, due dates and new tasks
- Placement: the Asana due date wins, even with a leftover `TODAY-` or `TOMORROW-<Name>` tag. Due today → Today, due tomorrow (next calendar day; Friday → Saturday) → Tomorrow, due the next Monday after today → Monday (`src:'d'` on the board item). Overdue, later, and undated tasks stay in Backlog, tags or not. Counters for Tomorrow use that calendar day; the Monday counter uses the next Monday. This replaces the old Friday→Monday shortcut.
- Every move through `/api/plan` also sets the date in the same call: Today = today, Tomorrow = the next calendar day, Monday = the next Monday (date only, replaces any due time), Backlog = no due date (due_on and due_at null). Dropping a task where it already is changes nothing. Tomorrow and Monday remove any `TODAY-`/`TOMORROW-` tags on that task and do not add a tag.
- `POST /api/task` `{name, notes, due_on, project, a, slot:{s,k}|null}` creates a task (the '+' on a section heading). Name must be more than the prefix (`054a `, `PRE `). Notes get D10M if the first line has no D-code. With a slot it is dated today, tomorrow, or Monday. Only a Today slot adds a `TODAY-<Name>` tag. The board's `projects` list (client-code projects and PRE general) is the fallback for a section's project.
- Meetings: each item has a `link` (Google Calendar event, `eid` = base64url of `<eventId> <calendar email>`, split-series `_R…` suffix dropped for instances; day view when the UID is not Google's). A meeting the person has not accepted (PARTSTAT TENTATIVE or NEEDS-ACTION) is omitted, the same as declined: not listed and not counted. `nt` is always 0.

## Calendar: all events (2026-10-28, replaces the client-meeting filter)
- Every accepted or own timed event is shown and counted. Tentative and unanswered (NEEDS-ACTION) invites are hidden, the same as declined and cancelled. Overlaps are merged when counting. Zero-length events show as a compact block (start time only) and add 0. All-day events are thin chips, never counted (`allday:[{title, link}]`). The header reads `Calendar · n · h:mm`. Only title, times and link leave the server. Listed events have no tent marker.
- Several feeds per person: `CAL_ICS_<NAME>` plus any `CAL_ICS_<NAME>_<SUFFIX>` (e.g. `CAL_ICS_DIMITRIS_PERSONAL`), in env or `data/cal.env`. They are combined into one day. The calendar id for links comes from the feed URL path.

## Hosting on Render (stateless, 2026-10-28)
- Everything required comes from env: `ASANA_PAT`, `ACCESS_KEY` (wins over `data/access_key`; required when `RENDER` is set, the server exits otherwise), `CAL_ICS_*` (wins over `data/cal.env`), `PORT`. Logs go to stdout/stderr.
- Today, Tomorrow and Monday are the Asana due date (`TODAY_STORE=asana_tags`, the default). Moving to Today may add a `TODAY-<Name>` tag. Moving to Tomorrow or Monday only writes `due_on` and never creates a `TOMORROW-*` or `MONDAY-*` tag. `data/tag_gids.json` is only a cache (also kept in memory); `TODAY_STORE=file` is a box-only fallback and warns on Render.
- Optional `DATA_DIR` moves the data folder. See `DEPLOY.md` and `render.yaml`.
